# GuliweRR — function reference

A curated, one-line-per-function index of the entry points most scripts need, grouped by category. It is a cheat sheet, **not an exhaustive list** — some public functions are not listed here. The exhaustive list is [`docs/reference/FullFunctionReference.html`](FullFunctionReference.html), generated from the live source: every public class, property, and method with its call signature and complete `help` text (INPUT/OUTPUT list with defaults, units, and design-rationale prose — the same text `help <name>` shows in MATLAB). Start here to find *which* function to call; go there for the full argument list.

All classes/functions below assume `run('guliwerr/init.m')` has already been run this session (see `docs/quickStart.md`). `guliwerrVersion()` returns the installed version (MAJOR.MINOR.PATCH; a `-dev` suffix means code between releases).

## Core building blocks (`guliwerr/core/`)

Build order for any calculation: `ElastConsts` → `Material` → `CalcParams` → `Structure`.

| Name | Purpose | Constructor | Key inputs |
|---|---|---|---|
| `ElastConsts` | Elastic constants (vector / 6×6 Voigt / 3×3×3×3 tensor forms) for one symmetry class. | `ElastConsts(consts, symmNo)` | `consts`: vector/Voigt/tensor; `symmNo` (opt, auto-detected if omitted — prefer passing it explicitly, `docs/pitfalls.md` NUM2) — see `@ElastConsts/SymmClassLibrary.m` for the constant count/order per symmetry (e.g. isotropic = `[c11,c44]`, cubic = `[c11,c12,c44]`) |
| `Material` | Elastic constants + density + crystal orientation for one layer. | `Material(elConsts, rho, dirMat, name)` | `elConsts`: `ElastConsts`; `rho`: density [g/cm³]; `dirMat` (opt, default: surface normal [100], propagation reference [001] — a {100}-type cut for a cubic crystal); `name` (opt) |
| `CalcParams` | Discretisation settings (Legendre order, depth) for one layer. | `CalcParams(relDepth, legOrder, realThickness)` | `relDepth` (default 20; the depth of the computational domain in wavelengths); `legOrder` (default 50; the Legendre polynomial order, i.e. the mesh resolution in depth) — **should satisfy `legOrder >= 2*relDepth`**, and `>= 2.3*relDepth` for the half-space `'ritz'` classification, see `docs/pitfalls.md` MTH1; `realThickness` (opt, real units, for `Structure.ApplyWavelength`) |
| `Structure` | A stack of layers (layer 1 = bottom/substrate). | `Structure(materIn, calcParamsIn, name, nMaxModes)` | `materIn`/`calcParamsIn` (opt, first layer — pass `[]` for `materIn` to skip); `name`; `nMaxModes` (default 500) |

`Structure` layer editing: `AddLayer(mater0, calcParams0)` (appends on top), `RemoveLayer(ind)`, `ModifyLayer(indLay, mater0, calcParams0)`, `ApplyWavelength(wavelengthReal)` (derives film `relDepth` from `realThickness`, substrate excluded — see `help Structure.ApplyWavelength`).

Most-used `ElastConsts` static helper methods (`ElastConsts.<Name>(...)`): `SymmClassLibrary` (symmetry-class names/constant counts), `FindSymmClass_input` (identify the symmetry class from an input), the form converters `Vector2Voigt`/`Voigt2Vector`/`Any2Tensor`, `RotateTensor`, `CubicConversion`/`CubicDeconversion` (and the `Tetragonal`/`Hexagonal` counterparts), and `VoigtAverages`/`ReussAverages`/`HillAverages` (Voigt/Reuss/Hill isotropic-average bounds, all returning `[M,G]`). Full list, with each one's `help` text: [`ElastConsts` in `docs/reference/FullFunctionReference.html`](FullFunctionReference.html#core-elastconsts).

`Material` static orientation-matrix helper methods (`Material.<Name>(...)`): `CompleteDirMat` (right-hand-complete a 2-row input), `CalcRotMat`/`RotDirMatFromAngle` (in-plane rotation), `GetStandardDirMat` (reorder into the internal solver frame — see `docs/reference/architecture/core.md`; the instance method `mat.GetStandardElastTensor(angleDeg)` gives the elastic tensor in that frame), `DirMat2Euler`/`Euler2DirMat` (`dirMat` ↔ Bunge-ZXZ Euler angles `(φ1,Φ,φ2)`, the same convention as MTEX and the orientation output of the Nottingham spatially resolved acoustic spectroscopy (SRAS) instrument) vs. the raw, non-`dirMat` `DCM2Euler`/`Euler2DCM` (which pair to use: `docs/pitfalls.md` OTH1), `Miller2DirMat`/`DirMat2Miller` (Miller/Miller-Bravais index ↔ direction-cosine row vector, general for all 7 crystal systems — call with just a `symmNo`, or `hkl`/`dirCos`=`[]`, to list which `latticeParams` fields that symmetry needs). One line each via `help Material.<Name>`.

Materials library: `Material.FromLibrary(name, dirMat, 'T', T, 'variant', v)` builds a `Material` from `guliwerr/data/materialsLibrary.csv` (single-crystal constants in GPa, density and crystal structure, each row with its primary reference and source; name or alias, case-insensitive; without `'T'`/`'variant'` the material's default row); `Material.ListLibrary()` prints or returns every row. It holds 48 common materials at room temperature — the metals and semiconductors of Levy, Bass & Stern Vol. II Tabs. 7.1/7.2 (with the standard Co and Ti sets), MgO, sapphire (`Al2O3`) and α-quartz — every row with a named primary measurement. A row marked `provisional` (secondary source only, or a doubt given in the row's note) would print a one-line note saying why; the shipped table has none. The StructureControl GUI has the same list as a "library material" dropdown per layer. While a library entry is selected its symmetry is locked; the "Hill avg" toggle beside the dropdown replaces the Cij by the isotropic Hill averages (c11 = M, c44 = G) and restores them when switched off — it works for hand-typed anisotropic Cij too.

## Half-space forward calculations (`guliwerr/forwardCalcs/`, `Calc` namespace)

`Calc` is a thin namespace over these classes — type `Calc.` for tab-completion of every entry point below. The classes themselves (`CalcSingleHS`, `CalcAngSweepHS`, ...) can also be constructed directly; `Calc.<name>` is the recommended entry point.

## Mode classification — which peaks are surface waves (`guliwerr/forwardCalcs/`)

> **Experimental.** Surface-wave classification is checked against the measured maps published in Grabec et al. 2024 and the UTGS paper (arXiv:2510.10696), and there is no general agreement on which spectral peaks count as surface waves in strongly anisotropic materials. Thresholds, scores and the interface may change.

Every `Calc.singleHS`/`singleLayered`/`angSweepHS`/`angSweepLayered`/`wavevecAngSweep2Layered` result is classified automatically. Existence of a surface wave is decided by one score per spectral peak against a standard you choose; the Ritz mode supplies identity; the label (`'Rayleigh'`/`'pseudoRayleigh'`, layered `'SAW'` plus `aboveSubstrateST`) comes from the velocity. Three methods, each with its own score class:

- `'green'` (default, needs `calcMode='full'`) — `GreenScore` (half-space) / `GreenScoreLayered` (layered) on the Green's function \|G13_eff\|;
- `'refined'` (half-space `'full'` only, on request) — `GreenSpotScore` on the Green's function averaged over the probe spot's directions;
- `'ritz'` (the only method on `calcMode='ritzOnly'`, also stored on every `'full'` result) — `RitzScore` on the Ritz modal sum.

Design, validation against the published measured maps, and known limits: `docs/reference/architecture/forwardCalcs_modeClassification.md`.

| `SawSpectrum` | Static class: the late-time machinery the three scores share (damping `ETA`, velocity axis, late-time gate, peak search; `architecture/forwardCalcs_modeClassification.md` §5). | `SawSpectrum.velocityAxis(vMax, step)`, `[A, vOut] = .lateTime(G, velAxis, vRef, pad, tailFrac, gatePeriods)`, `.candidates(G, velAxis, vSearchMax, ref, pad, tailFrac)` | |

Per entry of `significantModes` (in `.classification` of each single-angle result, `.significantModesMap{i}` of a sweep): `method` is the classification that produced it (empty on limiting entries); `score` its existence score on that method's own scale, `scoreDb` the same in dB; `grade` `'strong'` or `'weak'`; `matchScore` the Ritz match quality; `relPeakHeight` the peak's height over the tallest candidate at that angle (display only; it never decides existence). Every scored candidate of an angle, accepted or not, is in `classification.greenScorePeaks` (`'green'`), `classification.ritzScorePeaks` (`'ritz'`) or the result's `refinedSaw.peaks` (`'refined'`). Field meanings (all of them) and the scoring classes' constants: `docs/reference/architecture/forwardCalcs_modeClassification.md` (sections 8 and 9).

## Free plate (Lamb waves) forward calculations (`guliwerr/forwardCalcs/`, `Calc` namespace)

Homogeneous or multi-layered free-standing plate, both surfaces traction-free (`Structure` with `nLay >= 1`). Design rationale, mode-type classification, and zero-group-velocity (ZGV) points: `docs/reference/architecture/plate.md`. No `calcMode` argument anywhere in this family — there is no Green's-function analogue for a free plate in this codebase, so only the Ritz solve ever runs; `retentionLevel` is `'full'`/`'none'` only (no `'saw_only'` tier — every computed mode is a physical branch, so there is nothing to prune).

| Name | Purpose | Call | Key inputs |
|---|---|---|---|

## Solvers (`guliwerr/solvers/`)

The solvers the `Calc` containers run, callable on their own for custom work. `structure` is an ordinary (unrotated) `Structure`; `angle` rotates its `dirMat` in-plane, as everywhere else.

| Name | Purpose | Call | Key inputs |
|---|---|---|---|
| `Christoffel` | Bulk-wave (Christoffel) solutions; a static class, never instantiated. | `vels = Christoffel.phaseVels(elTensor, dirVec, rho)` → `[vL; vT1; vT2]`, descending. `[eigVals, eigVecs, GammaMat] = Christoffel.matrix(elTensor, dirVec, rho, normalizeDir)`. `vels = Christoffel.phaseVelScan(mater, angleDeg)` → `[3 × nAngles]`. `[vels, dVels, eigVecs] = Christoffel.phaseVelAngleDeriv(elTensor, angleRad, rho)`. `[vG, vP, eigVecs] = Christoffel.groupVelVectorsForDir(elTensor, dirVec, rho)` | `elTensor`: 3×3×3×3 tensor (e.g. `mater.elConsts.tensor`); `dirVec`: propagation direction in the tensor's frame; `rho` default 1 (density-normalised); `phaseVelScan` takes a `Material`; `phaseVelAngleDeriv` takes its angle in **radians** (the others, degrees). `docs/reference/architecture/christoffel.md` |
| `GreenSolver.calc` | The surface Green's function G_IJ(k, ω) of a half-space or a layered stack, over a velocity axis. | `g = GreenSolver.calc(structure, angle, velRange, forceDir, displDir, Name, Value, ...)` | `velRange` [km/s] default `linspace(0.1, 10, 5000)`; `forceDir` (I, default 1) and `displDir` (J, default 3): 1 = propagation, 3 = surface normal, so the default is G13. | `RitzSolverSAW` | Ritz (Legendre-basis) modes of a half-space or film stack on a substrate (SAW). | `rs = RitzSolverSAW(structure, angleDeg).calc(withDiagnostics, precompStruct)` | `withDiagnostics` default `true` (per-mode diagnostics); `precompStruct` (opt): the angle-independent precompute, as in `docs/pitfalls.md` NUM6. | `RitzSolverSAW.ritzSensitivities` | The lowest Ritz modes of a layered stack and the exact (Hellmann–Feynman) log-derivatives of their phase velocities with respect to every layer's elastic constants, density and depth, the angle and `|k|` — one solve, no finite differences (checked against central differences). | `CalcCommon.ritzWavelengthSweep` | The wavelength-independent part of the Ritz precompute (raw Legendre tensor, constraint basis), built once for a sweep over wavelengths. | `sweep = CalcCommon.ritzWavelengthSweep(structure)`; then `pre = CalcCommon.ritzSAWPrecompute(structure.ApplyWavelength(λ), sweep)` per wavelength | Equal to the from-scratch precompute; the Legendre orders must match (`CalcCommon:ritzSAWPrecompute:sweepMismatch`) |
| `RitzSolverLamb` | Ritz modes of a free plate (Lamb waves). | `rs = RitzSolverLamb(structure, angleDeg, realThickness, realWavVec).calc(withModeTypes, precompStruct)` | `realThickness`, `realWavVec`: physical units; `[]`/0 for normalised units only (a nonzero `realWavVec` needs `realThickness`); `withModeTypes` default `false` (adds `rs.modesType`, `rs.modeTypeConfidence`). | ↳ `RitzSolverLamb.locateZGV` | ZGV point nearest a seed on one raw mode, by Newton refinement. | `[wavVecZGV, freqZGV, rsAtZGV] = RitzSolverLamb.locateZGV(structure, angleDeg, realThickness, modeNo, wavVec0, precompStruct)` | `NaN` when Newton does not converge or leaves `[wavVec0/10, 10 wavVec0]`; prefer `.locateZGVs` on a sweep |
| ↳ `RitzSolverLamb.kPolynomial` | The plate eigenproblem as a polynomial in k: `(k² L2 + k L1 + L0) a = ω² M a`, ω = 2π f. | `poly = RitzSolverLamb.kPolynomial(structure, angleDeg, realThickness, precompStruct)` | fixed physical thickness; `poly.L2/L1/L0/M` in the constrained basis `poly.N` |
| `ZgvNewton.solve` | Newton iteration for one ZGV point of a `kPolynomial` operator (adapted from GEWtool's `ZGVNewtonBeta`, Kiefer et al. 2023). | `[k, omega, u, isConverged, nSteps] = ZgvNewton.solve(L2, L1, L0, M, k0, omega0, u0)` | `u0` opt (default: the eigenvector at `k0` nearest `omega0`); errors on a non-Hermitian operator; `NaN` + `isConverged = false` on no convergence, a singular Jacobian or a cut-off (k → 0) |

Axis ranges from a script: every map/curve viewer above has `gui.setAxisRange(axisName, [lo hi])` with `axisName` `'x'`, `'y'` or `'c'` (colour, map viewers only), e.g. `gui.setAxisRange('y', [NaN 7]); gui.setAxisRange('c', [-3 0])`. A `NaN` entry keeps that limit, `[]` keeps both. It fills the side-panel min/max fields exactly as typing would, so the range survives a drill-down, a slice step (wavelength, wavevector or omega0) and a mode switch; unlike typing, it errors on bad input and while a map viewer is drilled into a single angle. The combined, isoFreq-combined and `FreqAngSweep2Layered` viewers forward the call to their map; the double-sweep viewers forward it to the view of the current mode, and in dispersion mode there is no colour axis. Changing the graph type resets the colour range to the new plot's own scale.

## Inverse characterisation (`guliwerr/inverseCalcs/`, `Inv` namespace)

> **Experimental.** The inverse module is validated on synthetic data only; the interface may change. Its pseudo-surface-wave tracking is new.

Recover the elastic constants of one selected layer (half-space or one layer of a layered
structure) from measured SAW/pseudo-SAW/bulk-limiting velocities from one angular sweep, plus
optional pulse-echo phase velocities and a soft-fixed bulk modulus. `Inv.sensitivity`/
`Inv.elasticity` also accept `structure`/`association`/`measured` as **object arrays** (one
element per crystallographic cut of the same crystal) for a **joint multi-orientation
inversion** fitting one shared elasticity from several cuts at once; a single cut is just a
length-1 array. `Inv` is a thin namespace over these classes (same pattern as
`Calc`/`Vis`/`Gui`). Script-driven — start from
`examples/tutorials/tutorial_09_inversion_synthetic.m` (synthetic ground truth, a noisy and
incomplete measurement, inversion from a deliberately wrong guess).
